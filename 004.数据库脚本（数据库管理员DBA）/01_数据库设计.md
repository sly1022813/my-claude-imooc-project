# 数据库设计

## 一、数据库命名规范

### 1.1 数据库名称
```sql
CREATE DATABASE IF NOT EXISTS `light_accounting`
    DEFAULT CHARACTER SET utf8mb4
    COLLATE utf8mb4_unicode_ci;
```

**命名原则：**
- 使用小写字母和下划线
- 名称具有业务含义
- 不超过 64 个字符

### 1.2 命名规范

| 对象类型 | 命名规则 | 示例 |
|---------|---------|------|
| 表 | `业务含义` | `users`, `account_records` |
| 主键 | `表名_id` | `user_id`, `record_id` |
| 外键 | `参照表_参照列` | `user_id` (参照 users 表) |
| 索引 | `idx_表名_列名` | `idx_users_username` |
| 唯一索引 | `uk_表名_列名` | `uk_users_username` |
| 视图 | `v_业务含义` | `v_monthly_stats` |

## 四、核心表关系说明

### 4.1 用户与账目记录 (1:N)
- 一个用户可以有多个账目记录
- 删除用户时，账目记录保留（软删除）

### 4.2 分类与账目记录 (N:1)
- 一个分类可以有多个账目记录
- 分类有 `type` 字段区分收入/支出

### 4.3 用户与客户/供应商 (1:N)
- 一个用户管理多个客户/供应商
- 客户/供应商有各自独立的余额表

## 五、索引设计

### 5.1 主键索引
- 所有表都有自增主键 `id`

### 5.2 唯一索引
- `users`: `username` (用户名唯一)
- `categories`: `(user_id, name, type)` (用户下分类名唯一)

### 5.3 普通索引
| 表名 | 索引字段 | 说明 |
|------|---------|------|
| `account_records` | `user_id`, `type`, `created_at` | 用于统计查询 |
| `account_records` | `category_id` | 按分类查询 |
| `customers` | `user_id` | 按用户查询客户 |
| `suppliers` | `user_id` | 按用户查询供应商 |

---

## 六、安全性设计

### 6.1 密码存储
- 使用 bcrypt 算法加密
- 不存储明文密码

### 6.2 SQL 注入防护
- 使用预处理语句 (Prepared Statements)
- 输入参数严格校验

### 6.3 敏感操作日志
- 用户注册、登录、删除等操作记录日志

---

## 七、性能考虑

### 7.1 分表策略（未来扩展）
- `account_records` 按月份分表
- 历史数据归档到冷存储

### 7.2 缓存策略
- 用户会话信息使用 Redis 缓存
- 热门统计结果缓存

### 7.3 查询优化
- 避免 SELECT *
- 使用 LIMIT 分页
- 合理使用覆盖索引
